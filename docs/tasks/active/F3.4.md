## Contrato técnico congelado

1. `PathGuard` exige uma raiz autorizada explícita, existente e diretório; nunca usa `cwd`, home ou
   project root implícitos.
2. Entrada relativa é ancorada na raiz; entrada absoluta é aceita somente se resolver dentro dela.
3. Qualquer componente `..` é rejeitado antes da resolução, mesmo quando normalizaria para dentro.
4. Resolução canônica segue symlinks e junctions existentes, inclusive para um destino ainda não
   criado sob um ancestral existente; escape da raiz falha fechado.
5. Escrita na própria `.git` ou em qualquer descendente é rejeitada sem distinção de caixa.
6. Leitura de arquivo existente usa tamanho real; escrita exige tamanho pretendido inteiro e não
   negativo. Limites configurados são inteiros positivos e falham fechado quando excedidos.
7. O resultado tipado contém o path absoluto canônico para o consumidor e apenas o path relativo em
   formato POSIX para journal. O guard não cria, lê, escreve ou remove conteúdo.
8. Erros são tipados e não retornam sucesso sintético. Nenhuma capability/registration é criada.
9. Consumidores futuros devem revalidar imediatamente antes do efeito; integração pertence aos gates
   F3.5/F3.6/F3.8 conforme DEC-013.
