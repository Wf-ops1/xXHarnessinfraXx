## Contrato técnico congelado

1. `PythonAstIndexer.rebuild(revision="HEAD")` resolve a revisão transitória pelo mecanismo F4.1 e
   associa toda saída somente ao SHA Git completo de 40 caracteres comprovado.
2. O rebuild enumera blobs regulares `.py` da árvore do commit resolvido, em ordem determinística, e
   lê o conteúdo pelos object IDs Git. Working tree sujo, arquivos não rastreados e symlinks não entram
   no snapshot e jamais são rotulados com o SHA do commit.
3. O parser usa exclusivamente `ast` da biblioteca padrão sobre os bytes commitados, respeitando o
   encoding Python. Ele produz módulos, classes, funções síncronas/assíncronas, métodos e imports; não
   inventa símbolos fixos e aceita snapshot vazio somente quando o commit realmente não contém Python.
4. Módulos usam nome qualificado derivado do path POSIX (`pkg/__init__.py` → `pkg`,
   `pkg/mod.py` → `pkg.mod`; `__init__.py` raiz → `__init__`). Classes e funções acumulam escopo
   léxico; função cujo pai léxico imediato é classe usa kind `method`, as demais usam `function`.
5. Um símbolo de import é emitido por alias. `name` é o binding local; `qualified_name` é o alvo
   importado, incluindo pontos relativos. O intervalo é o statement completo.
6. `line_start` inclui decorators quando presentes; `line_end` usa o fim real do nó. O módulo cobre
   da linha 1 até ao menos 1. A ordenação final é estável por path, posição, kind, nome qualificado e nome.
7. Erro Git, path/objeto inválido, decode ou `SyntaxError` falha explicitamente como
   `StructuralIndexBuildError`, cita o path seguro quando aplicável e não publica snapshot parcial.
8. Somente depois de todos os arquivos serem parseados o resultado é entregue ao `SnapshotManager`.
   Digest, schema, status, publicação atômica, idempotência e conflito continuam exatamente sob F4.1.
9. `harness index` executa o rebuild completo do commit atual e só declara sucesso depois de recarregar
   o snapshot íntegro. `CodebaseMemoryAdapter` permanece consumidor read-only e nunca indexa por efeito
   colateral de uma consulta.
10. O backend Codebase-Memory MCP futuro deverá produzir o mesmo contrato, mas seleção de backend,
    incrementalidade, lease, ponteiro `current`, GC e memória semântica não pertencem a este gate.

## Rollback

### Gatilhos

- snapshot refletir working tree/untracked em vez do commit resolvido;
- símbolo fixo, path/qualname/linha incorreto ou ordenação/digest não determinístico;
- erro de um arquivo publicar resultado parcial, sobrescrever snapshot divergente ou deixar temporário;
- CLI declarar sucesso sem snapshot íntegro recarregado;
- correção exigir schema/dependência/CI/componente proibido ou qualquer aceite falhar.

### Procedimento não destrutivo

Parar e preservar diff/saídas. Antes de commit, inverter somente hunks F4.2 com `apply_patch`; depois de
commit, usar `git revert` nos commits exclusivos desta branch. Nunca usar `git reset --hard`, `clean`,
checkout amplo, apagar `.harness` do usuário ou sobrescrever snapshot existente. Ampliação material
exige registrar evidência, recongelar e criar novo checkpoint.

### Verificação pós-rollback

Repetir testes F4.1/F4.2 aplicáveis, `git diff --check` e auditoria contra `checkpoint/f4.2-ready`;
comprovar que contrato/CLI retornaram ao checkpoint e que nenhum estado do usuário foi removido.
