## Problema comprovado

No baseline, o comando não media o ambiente. `HealthProbe.probe_component()` fabricava os seis
estágios como `OK`, e `DoctorChecker` aplicava esse resultado genérico a quatro nomes fixos.
`harness doctor` sempre encerrava com código zero; não resolvia a configuração efetiva, não
selecionava workflow e não oferecia saída JSON.

Probe negativo executado antes de qualquer edição de produto:

```text

exit code: 0
resultado: Git CLI, Serena MCP, Codebase-Memory MCP e LLM Providers exibidos como saudáveis 6/6

... doctor --json
exit code: 2 — No such option '--json'

... doctor --workflow new-feature
```

sintética sem configuração, transporte, autenticação ou smoke real.

## Contrato técnico congelado

1. Todo componente é avaliado, nesta ordem, pelos estágios `Configured`, `Installed`, `Reachable`,
   `Authenticated`, `Capable` e `Healthy`; nenhum estágio recebe sucesso sem observação real.
2. Status de estágio são fechados: `PASS`, `FAIL`, `SKIPPED` e `NOT_APPLICABLE`. Falha bloqueante
   impede os estágios dependentes, que ficam `SKIPPED`; ausência legítima recebe `NOT_APPLICABLE`
   com motivo explícito e nunca é convertida em `PASS`.
3. Componentes obrigatórios: Git, Python/toolchain, provider selecionado, state storage, permissões
   de worktree e gates requeridos. O MCP selecionado é obrigatório apenas quando habilitado na
   configuração efetiva; MCP desabilitado fica explicitamente não aplicável e não causa falha.
4. `ConfigResolver` é a única origem de configuração. O doctor não cria defaults paralelos, não lê
   credencial implícita fora do resolvedor e não altera configuração, estado, worktree ou remoto.
5. Git e Python usam descoberta real de executável e subprocessos por `argv`, com timeout. Git
   comprova repositório/worktrees por comandos somente leitura; Python comprova versão suportada e
   import do pacote no runtime corrente.
6. O provider selecionado usa endpoint de descoberta/read-only compatível com seu adapter. Alcance,
   autenticação e capacidade são inferidos somente da resposta observada; segredo, header, token,
   corpo arbitrário e URL com credencial nunca aparecem no resultado, erro ou `repr`.
7. Serena habilitada reutiliza `SerenaAdapter.probe()` e valida sessão, tools e raiz ativa. Backend
   MCP sem adapter operacional falha em `Installed` ou `Capable`; não recebe simulação de produção.
8. State storage e worktree executam inspeção confinada e somente leitura de raiz, existência, tipo,
   permissões efetivas declaradas e vínculo Git. O smoke não cria arquivo, branch ou worktree.
9. Com `--workflow`, gates são derivados da composição canônica e seus comandos efetivos são
   resolvidos sem execução. Workflow ausente/inválido ou executável obrigatório ausente falha
   fechado. Sem `--workflow`, o componente permanece visível como `NOT_APPLICABLE`.
10. `harness doctor`, `harness doctor --json` e `harness doctor --workflow new-feature` usam o mesmo
    resultado tipado. Texto e JSON preservam ordem determinística de componentes/estágios.
11. O JSON possui versão de schema, status agregado, workflow opcional, componentes, estágios,
    códigos/mensagens redigidos e duração limitada; não serializa configuração bruta ou valores de
    ambiente. Saída idêntica recebe estrutura estável, desconsiderando duração observacional.
12. Qualquer componente obrigatório `FAIL` produz status agregado não saudável e exit code diferente
    de zero. Erro inesperado de probe é convertido em falha redigida do componente, nunca em crash
    cru nem falso sucesso.

## Critérios de aceite congelados

  agregação mandatory/optional e conversão redigida de exceções.
- Cada componente mínimo possui caso saudável e ao menos um caso negativo realista: config ausente,
  binário ausente, transporte inacessível, credencial rejeitada, capability ausente, storage/root
  inválido, permissão insuficiente, workflow/gate inválido ou executável de gate ausente.
- Provider e Serena usam transporte/controladores injetados apenas nos testes; nenhuma condição de
  teste entra no caminho de produção.
- `doctor --json` é parseável, determinístico e não contém canários de segredo em sucesso, falha,
  timeout ou exceção. O relatório Rich nasce do mesmo objeto do JSON.
- Os três comandos congelados são cobertos por `CliRunner`; componente obrigatório ruim encerra com
  código não zero e componente opcional desabilitado não derruba o comando.
- O probe negativo de Git com `PATH` vazio passa a falhar no estágio correto e o comando deixa de
  retornar zero.
- Testes atuais de encoding e lifecycle são atualizados para a semântica real, sem relaxar asserts
  alheios.
- Antes de `COMPLETED_LOCAL`: dedicado doctor/CLI; regressões config/models/Serena/storage/worktree/

Qualquer dependência nova, escrita em probe, saída de segredo, falso positivo, skip novo, relaxamento

- `harness doctor`, `harness doctor --json` e `harness doctor --workflow new-feature` compartilham o
  mesmo resultado. Qualquer componente obrigatório ruim encerra com código diferente de zero.
