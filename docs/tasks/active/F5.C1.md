## Problema comprovado

### Evidência negativa 1 — chaves sensíveis camelCase atravessam a configuração

```text
$env:F5_CONFIG_SAMPLE='credential-visible-value'; .\.venv\Scripts\python.exe -c "import os; from pathlib import Path; from ai_engineering_harness.core.config import ConfigResolver; r=ConfigResolver(Path.cwd()); c=r.resolve(); c['project']={'deployToken':os.environ['F5_CONFIG_SAMPLE'],'apiKey':os.environ['F5_CONFIG_SAMPLE'],'privateKey':os.environ['F5_CONFIG_SAMPLE']}; print(r.validate_and_redact(c)['project'])"
```

Resultado observado, exit code `0`:

```text
{'deployToken': 'credential-visible-value', 'apiKey': 'credential-visible-value', 'privateKey': 'credential-visible-value'}
```

Local: `src/ai_engineering_harness/core/config.py::_is_sensitive_key`. A normalização atual aplica
somente `casefold()` e troca hífen por underscore; não separa camelCase/PascalCase/acrônimos. Como
`project` aceita JSON estrito arbitrário, o valor pode alcançar a configuração/bundle persistido.

### Evidência negativa 2 — atribuição sensível citada com espaço atravessa o redator

```text
$env:F5_SAMPLE='password="visible password"'; .\.venv\Scripts\python.exe -c "import os; from ai_engineering_harness.security import Redactor; print(Redactor.redact_text(os.environ['F5_SAMPLE']))"
```

Resultado observado, exit code `0`:

```text
password="visible password"
```

Local: `src/ai_engineering_harness/security/redaction.py::_assignment_pattern`. O ramo atual aceita
somente valores sem whitespace, mesmo quando há aspas, e pode deixar texto sensível em superfícies
que usam `redact_text` antes de persistir stdout, stderr ou evidência.
